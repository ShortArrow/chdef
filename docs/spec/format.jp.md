# ファイル形式と列

🌐 [English](./format.md) | **日本語**

実装済み（0.0.15）: 先頭 BOM の除去、英語 / 日本語の見出し名による列特定（先頭 9 列の位置フォールバックと、読み手に教えた綴り `ColumnAliases` を含む）、空行と `#` 行の読み飛ばし、下表の全列の解釈と Issue、`parse_*_csv_bytes` によるバイト列入力、`load_*_csv` の `AsRef<Path>` 受け取り。書き出しは `to_csv` で、往復の保証は [editing.jp.md §2](./editing.jp.md)。chdef が作るファイルは、呼び出し側が指定した列と言語で見出しを書く（`with_columns`）。

## 1. ファイル

| 項目 | 読み | 書き |
|---|---|---|
| 文字コード | UTF-8。先頭の BOM（`EF BB BF`）は 1 個以上あっても全て無視する | 読んだファイルのとおり。chdef が新規に作るファイルは UTF-8 で BOM 付き（表計算ソフトが別の文字コードと誤判定しないため）|
| レコード区切り | `\r\n` と `\n` の両方を受け付ける | 読んだファイルのとおり。chdef が新規に作るファイルは `\r\n` |
| セル内改行 | 引用符で囲まれたセル内の `\n` / `\r\n` はセルの一部（RFC 4180） | 元の文字列を変えずに書く（`\n` を `\r\n` に正規化しない） |
| 引用 | `"..."`。内部の `"` は `""`。引用符の外の `"` は文字として扱う | `,` `"` `\r` `\n` のいずれかを含むセルを引用する |
| 空白 | セルの前後の空白（半角スペース・タブ）は取り除いて解釈する | 取り除かない（原文を保つ） |
| 空行 | 全セルが空の行は読み飛ばす（Issue なし） | — |
| コメント行 | 先頭セルが `#` で始まる行は読み飛ばす（Issue なし） | — |
| 空ファイル / 見出しのみ | チャンネル 0 件、Issue なし | — |

**デコードの担当**: chdef が読むのは UTF-8 だけで、文字コードの推測はしない。`parse_ch_csv` は呼び出し側がデコード済みのテキストを受け取る。`parse_ch_csv_bytes` はバイト列を受け取り、BOM を落として UTF-8 として解釈し、解釈が止まったバイト位置を返す。表計算ソフトが CP932 で書き出したファイルは、呼ぶ前に利用側がデコードする。

**引用の理由**: セル内改行を引用しないで書くと、次の読み込みで 1 行が複数レコードに割れ、続きの行が `番号` に見えない値を持つ幽霊行になる。読み側は幽霊行を `番号` の検査で捨てるが、失われた `備考` は戻らない。

## 2. 列の特定

列は **見出し名**で特定する。手順は 3 段:

1. 見出し行をセルに切り崩す（§1）。この時点では何の意味も与えない。
2. 各セルを、**使用中の語彙**で列に対応づける。
3. そのうえで、本書が言うとおりに列として解釈する。

列は **正準名**を 1 つ持つ。小文字 ASCII で、§3・§4 に挙げてある。その名前が列の同一性そのもので、本書でも、[interchange.jp.md](./interchange.jp.md) の JSON でも、chdef が提供する全ての API でも同じ。見出しがそれ以外に何と書いていようと、それは語彙である。

**語彙は呼び出し側が渡すデータ**であって、chdef が知っている言語ではない。読むときは綴りを列に対応づけ、chdef が新規に作るファイルに書く綴りを決める。1 つの列に最初に教えた綴りが、書かれる綴りになる。chdef は 1 つ同梱する（`ColumnVocabulary::japanese()`。下表）が、呼び出し側が組む語彙に対して何の特権も持たない。どの言語の見出しも、その綴りを教えれば読める。

語彙が何であれ、chdef は **正準名と §3・§4 が挙げる異綴り**も認識する。これらが同一性であり、語彙はそれを置き換えるのではなく足すものだから。セルは前後空白を除き、大文字小文字を区別せずに照合する。見出しに無い列は「未指定」として扱い、エラーにしない。**知らない列は保持し、そのまま書き戻す**。

見出し行が無い、または `number` 列が見つからない場合は、列を正順と**みなす** — CH CSV なら先頭 9 列、BF CSV なら 5 列。この場合 Issue `header_assumed` を 1 件報告する。

見出し名は読んだままの綴りで書き戻す。新規に作るファイルは、呼び出し側が指定した列を、指定した語彙の綴りで並べる（`ChTable::with_columns`）。既定は全列を正準の順で、正準名で。

呼び出し側が何を教えても形式が形式であり続けるための規則は 2 つ:

- **語彙は足すだけ。** セルはまず正準名と異綴りに照合するので、正準名は常に本書が言うとおりの意味を持つ。`number` に別の意味を教えても何も起きない。
- **語彙はゴールデンベクタに現れない**（[interchange.jp.md §3](./interchange.jp.md)）。準拠は正準名だけで定義されるので、他言語の実装は語彙を 1 つも提供する義務を負わない。

## 3. CH CSV

正順の見出し（17 列形式）:

```
number,bytes,bits,section,name,type,lsb,offset,unit,min,max,default,memo,var,format,favorite,kind
```

同じ列を §2 の日本語語彙で綴ったもの:

```
番号,バイト数,ビット数,セクション名,メッセージ名称,型,LSB,オフセット,単位,値(最小),値(最大),値(デフォルト),備考,変数名,表示形式,お気に入り,種別
```

先頭 9 列 + `値(デフォルト)` だけの 9〜10 列形式も同じ規則で読む。

| 列 | 異綴り | 必須 | 解釈 |
|---|---|---|---|
| `number` | `no`, `CH`, `ChNumber` | **必須** | 1 以上の整数。空欄・非整数・0 以下は**行ごと読み飛ばし**（Issue `channel_number_invalid`）。全セルが空の行と `#` 行は Issue なしで読み飛ばす。上限は設けない（u32） |
| `bytes` | — | 任意 | 1〜8 の整数。空欄・非整数 → `型` の幅（下記）、それも無ければ 2（Issue `bytes_assumed`）。範囲外 → 1〜8 に丸めて Issue `bytes_out_of_range` |
| `bits` | — | 任意 | 読まない。保持して書き戻す |
| `section` | — | 任意 | 文字列。空欄はセクション無し |
| `name` | `SignalName` | 任意 | 文字列 |
| `type` | `DataType` | 任意 | 接頭辞 2 文字（大文字小文字不問）`UI` / `SI` / `BF` と、任意の幅サフィックス（`UI8` `SI16` `UI32` `SI64` …）。空欄・不明 → `UI`（Issue `type_assumed`）。幅は常に `バイト数` から決まり、サフィックスと食い違えば `バイト数` が勝つ（Issue `type_width_mismatch`） |
| `lsb` | `Scale` | 任意 | 実数。空欄・`0` → `1`。それ以外の有限値はそのまま（負も可）。非数・無限 → `1`（Issue `lsb_invalid`） |
| `offset` | — | 任意 | 実数。空欄 → `0`。非数 → `0`（Issue `offset_invalid`） |
| `unit` | — | 任意 | 文字列 |
| `min`, `max` | — | 任意 | 空欄 → 未指定。数値 → **物理値**の境界（有限の f64）。`0x` / `0X` → **生値**の境界で、`値(デフォルト)` と同じく幅を検査（Issue `raw_out_of_range`、下位ビットを採用）。それ以外 → 未指定（Issue `min_invalid` / `max_invalid`）。解決後の `min` が `max` を上回る場合は両方保持（Issue `min_max_swapped`）。変換には自動適用せず、`range_contains` / `clamp_to_range` が明示の問い合わせ |
| `default` | `DefaultValue` | 任意 | 空欄 → 未指定。`0x` / `0X` 接頭辞 → 16 進の生値。それ以外 → 10 進の**生値**（整数）。どちらの記法でもチャンネルの幅を持ち、幅を超えたら下位ビットを採用（Issue `raw_out_of_range`）。どちらの記法でもなければ未指定（Issue `default_invalid`）。BF 型では BF CSV の既定値がビット単位で上書きする（[conversion.jp.md](./conversion.jp.md)） |
| `memo` | `Description` | 任意 | 文字列 |
| `var` | `variable` | 任意 | 文字列。保持のみ |
| `format` | `DisplayFormat` | 任意 | `DEC` / `HEX`（大文字小文字不問）。空欄・不明 → `DEC`。`HEX` で `LSB` が 1 以外なら Issue `raw_display_with_lsb`。この列が選ぶのは**どちらの読みを表示するか**（物理値か生値か）であって、印字する基数ではない（[conversion.jp.md §7](./conversion.jp.md)）。変換には影響しない |
| `kind` | — | 任意 | `plain` / `const` / `counter` / `derived`。前後空白を除き、大文字小文字を区別しない。空欄 → `plain`。それ以外 → `plain`（Issue `kind_assumed`）。**このチャネルの値を誰が決めるか**だけを記録し、他には何も意味しない。`encode` の挙動は何が書かれていても同じで、chdef がこの列を理由に値を埋めることはない（§5）|
| `derived` | — | 任意 | `derived` のチャンネルをどう算出するか（§6）。`kind` が `derived` のときだけ読み、それ以外では無視する。読めなければ、そのチャンネルは `値(デフォルト)` のままで何も算出しない（Issue `derived_invalid`）|
| `favorite` | `IsFavorite` | 任意 | `1` または `true`（大文字小文字不問）→ 真、それ以外 → 偽。書き出しは `1` / `0` |

`型` の接頭辞と幅の対応: 幅は `バイト数 × 8` ビット。`UI` は符号なし整数、`SI` は 2 の補数の符号付き整数、`BF` はビットの集まり（値としては符号なし）。

## 4. BF CSV

```
number,bit,name,default,memo
```

| 列 | 異綴り | 必須 | 解釈 |
|---|---|---|---|
| `number` | `no`, `CH` | **必須** | 親チャンネルの `番号`。空欄・非整数 → 行ごと読み飛ばし（Issue `bf_parent_invalid`） |
| `bit` | `BitNumber` | **必須** | 0 以上の整数、親の幅 `バイト数 × 8` 未満。非整数 → 行ごと読み飛ばし（Issue `bf_bit_invalid`）。幅以上 → 読み飛ばし（Issue `bf_bit_out_of_range`）。親が未定義、または親の `型` が `BF` でない → 読み飛ばし（Issue `bf_parent_not_bitfield`） |
| `name` | `SignalName` | 任意 | 文字列 |
| `default` | — | 任意 | `0` / `1` のみ有効。空欄 → 未指定（親の既定値のビットを保つ）。それ以外 → 未指定（Issue `bf_default_invalid`） |
| `memo` | — | 任意 | 文字列 |

BF CSV は `型` が `BF` のチャンネルの分だけあればよく、全チャンネルを列挙する必要はない。1 行は 1 ビット。ビット範囲（`3:1` のような複数ビット）は 0.0 系では表現しない。

## 5. チャネルの値を誰が埋めるか

`kind` は、そのチャネルの値がどこから来るかを記録する。事実が行と一緒に動くようにするため。チャネルを挿入すると以降の番号が全て繰り下がり、コード中の定数や別ファイルの対応表はその瞬間に黙って嘘になるが、セルはそうならない。

| `kind` | 意味 |
|---|---|
| `plain` | 呼び出し側が値を渡すか、チャネルが `default` を取る。 |
| `const` | 値は `default` で、フレームごとに変わらない — 同期語、プロトコル版数など。 |
| `counter` | 呼び出し側が、フレームごとに進む数を渡す。 |
| `derived` | chdef がフレームの残りから算出する。手順は `算出` 列（§6）。|

**chdef は列を読み、保持し、書き戻し、読めなかったものを報告する。** `encode` が出すバイト列は `kind` が何であっても同じ。`derived` は chdef が算出できる唯一の種別だが、それでも `encode` の中では算出しない。フレームを封じるのは独立した呼び出し（§6）。`const` のチャネルを上書きしても Issue にはならない — 呼び出し側が何を送ってよいかは、呼び出し側が決めることだから。

`counter` を chdef が進めないのは、カウンタが**フレームを送る線に属する**ものだからで、1 つの定義を複数の線が共有し、線ごとに別の番号が回ることがある。**巡回させるのも呼び出し側**である: 生値がチャネルの幅を超えると下位ビットが残る（§3、Issue `raw_out_of_range`）のに対し、物理値が幅を超えると飽和する（[conversion.jp.md §2](./conversion.jp.md)）。したがってカウンタは、チャネルの幅に落としたうえで生値として渡す。

この 3 つ以外の値が現れることはある。知らない値を受けた読み手はそれを `plain` として扱い、そう報告するので、後の chdef 向けに書かれたファイルもとりあえず読める。

## 6. 算出チャンネル

`種別` が `derived` のチャンネルは、フレームの残りから算出する。どう算出するかは `算出` 列が言う。今のところ手順は 1 つ:

```
crc16/x25 1..7
^^^^^^^^^ ^^^^
手順      対象のチャンネル範囲。両端を含む
```

- **範囲が名指すのはバイトではなくチャンネル**で、`番号` で指す。チャンネルを挿入すれば以降の番号は繰り下がり、範囲もそれに追従する — バイト範囲ではそうならない。対象はレイアウト順に走査する。レイアウトが持たない `番号` は Issue で、その手順は何も算出しない。
- **範囲は必須で、既定値は無い。** 同期語・長さ・データ・CRC と並ぶフレームでも、対象がデータだけのことも、長さとデータのことも、CRC 以外の全部のこともある。そのどれかは機器のプロトコルの性質であって、CRC の性質ではない。既定を置けば多くの場合は当たり、外れたときは黙って間違う — 黙って間違った CRC は、ハードウェアが理由も告げずにフレームを捨てる形で現れる。範囲の無い手順は `derived_invalid`。
- **対象が 1 続きでないときは範囲を並べられる**: `crc16/x25 2..3,5..7`。各範囲は `低..高` で両端を含み、書かれた順に左から走査する。
- **手順の実体は 6 つの数**。あらゆる CRC がこの型で記述できる: 幅、生成多項式、初期値、入力を反転するか、出力を反転するか、最後に XOR する値。書き下すと上の行はこうなる。

  ```
  crc16 poly=0x1021 init=0xFFFF refin=1 refout=1 xorout=0xFFFF 1..7
  ```

  chdef はカタログ済みの変種を名前として同梱する。`crc16/x25` は上の 6 つの数そのもので、名前が数に対して持つ特権は無い。どのカタログにも無い CRC の機器向けのファイルは、数を書く。
- セルがそれ以外なら Issue `derived_invalid`。そのチャンネルは `値(デフォルト)` のままで、何も算出しない。

この chdef が同梱する名前と、それが表す数、そして同定に使うチェック値（ASCII `123456789` の CRC。どの CRC カタログも載せる自己テスト値）:

| 名前 | 幅 | poly | init | refin | refout | xorout | check |
|---|---|---|---|---|---|---|---|
| `crc16/x25` | 16 | `0x1021` | `0xFFFF` | あり | あり | `0xFFFF` | `0x906E` |
| `crc16/ibm-3740` | 16 | `0x1021` | `0xFFFF` | なし | なし | `0x0000` | `0x29B1` |
| `crc16/kermit` | 16 | `0x1021` | `0x0000` | あり | あり | `0x0000` | `0x2189` |
| `crc16/xmodem` | 16 | `0x1021` | `0x0000` | なし | なし | `0x0000` | `0x31C3` |
| `crc8/smbus` | 8 | `0x07` | `0x00` | なし | なし | `0x00` | `0xF4` |
| `crc32/iso-hdlc` | 32 | `0x04C11DB7` | `0xFFFFFFFF` | あり | あり | `0xFFFFFFFF` | `0xCBF43926` |

どのカタログにも無い CRC の機器は数を書く。CRC ですらないものを使う機器も詰まない — 対象範囲は読まれるので、`covered_bytes` がそのバイト列をそのまま渡す。

### 封じることと、検めること

`encode` は算出チャンネルを埋めない。**封じるのは独立した呼び出し** `ChannelLayout::seal` で、フレーム中の全ての算出チャンネルをレイアウト順に埋める。手順は「送られる姿のバイト列」を読むので、封じるのは他の値が全て入った後に 1 度だけ。

逆向きには `derived_mismatches` があり、格納された値が手順と食い違う算出チャンネルごとに Issue `derived_mismatch` を返す。受信側が行う検めで、chdef が「このフレームは間違っている」と言う唯一の場所。

どちらも `encode` / `decode` が適用することはなく、どちらも記憶されない。
