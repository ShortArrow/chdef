# 編集

🌐 [English](./editing.md) | **日本語**

実装済み（0.0.2）: 下記の全部（`ChTable` / `BfTable`: parse / `to_csv` /
セル・行の編集 / `insert_channel` / `insert_channel_renumbering`）。編集
**UI**・undo履歴・保存のオーケストレーションは対象外 — Table は値なので、
利用側は clone でスナップショットを取れる。

## 1. 編集するのは Table

Table 段階（[layout.jp.md §1](./layout.jp.md)）は、見出し行と全データ行を
セル文字列のまま保持する — コメント行・空欄行・未知列も含めて。編集
セッション中の一次情報はここ。

ここまでが `Grid` で、列の語彙を必要としない。列を読まずにファイルを
表示・編集する利用側は `Grid` を使い、CH と BF の表を選び分けない。
`ChTable` / `BfTable` は Grid に見出しが名指す列を加えたもので、語彙が
必要なものだけを足す — 行の解釈、型付きチャンネルの挿入、番号の付け替え、
横断検査。素の Grid が行う唯一の解釈は「最初のレコードが見出しか」で、
最初のレコードを見出しとみなす。語彙から判定する（位置フォールバックを
含む [format.jp.md](./format.jp.md) §2）のは型付きの表の仕事。

Rows / Layout は導出ビューで、編集したら解釈し直す（`channels()` /
`bitfields()` → `build_layout`）。位置や `total_bytes()` が常に再計算される
のと同じ原則で、何もキャッシュしないから何も陳腐化しない。

## 2. 往復の保証

読む → Table → 書く で保存されるのは**行・セルの内容・ファイルの形**:

- 見出しの表記、未知列、コメント行、全セル空の行はそのまま残る。
- 引用は書き出し規則（[format.jp.md §1](./format.jp.md)）に正規化される:
  `,` `"` 改行を含むセルだけ引用し、元ファイルの不要な引用符は落ちる。
- BOM とレコード区切りは読んだとおりに書き戻す（`CsvStyle`）。`\n` 区切りで
  管理しているファイルの 1 セルを編集しても、全行が書き換わることはない。
  コード上で作った表は [format.jp.md §1](./format.jp.md) の既定
  （BOM と `\r\n`）で書く。形は読み書きでき、全ファイルで統一したい
  プロジェクトは自分で指定できる。
- セルが 1 個もない行（カンマすらない完全な空行）はレコードにならず、
  保存されない。残したい読み飛ばし行は `,,,` と書く。

したがって、既に書き出し規則に従っているファイルはバイト単位で往復する。

## 3. 編集操作

- `header` / `rows` / `row(index)`: 書き出される形のグリッド。見出し行
  （位置指定で読んだファイルには無い）と、コメント行・空行を含む全データ行。
- `cell` / `set_cell(row, col, value)`: グリッド。0 始まり・見出し除外
  — Issue の行番号と同じ数え方。短い行の先に書けば空セルで埋まる。
- `insert_row` / `append_row` / `remove_row`: 生の行。グリッドエディタ用。
  3 つとも全域関数で、範囲外の位置は切り詰め・無視・`None` になり panic しない。
- `insert_channel(row_index, &ChannelDef)`: 型付き定義を**このファイルに
  ある列**に描画する。列がないフィールドは落ちる。描画規則: `表示形式` は `DEC` / `HEX`、`お気に入り` は `1` / `0`、`セクション名` / `メッセージ名称` / `単位` / `備考` / `変数名` はそのまま、`番号` /
  `バイト数` / `値(デフォルト)` は 10 進、`型` はカテゴリのみ（`UI` /
  `SI` / `BF` — 幅は `バイト数` が持つ）、`LSB` / `オフセット` は最短の
  10 進表記、`値(最小)` / `値(最大)` は各自の記法（物理値は数値、生値は
  `0x`）。

## 4. グリッド上の横断検査

`BfTable::cross_issues(&channels)` は、レイアウトの横断検査
（`bf_parent_not_bitfield` / `bf_bit_out_of_range`）を行がまだ生きている
場所で実行する。指摘はグリッドの行と `番号` / `BIT番号` の列を持つので、
エディタは行なしのメッセージではなくセルを赤くできる。`番号` / `BIT番号`
が読めない行は `bitfields()` が行つきで報告済み。

## 5. 番号の付け替え

`insert_channel_renumbering(row_index, &def, Some(&mut bf_table))` は
連番維持の挿入: `番号` ≥ `def.number` の全チャネルを +1 し（`番号` セルを
書き換え）、BF 行は親に追従し、そのうえで新しい行を挿入する。戻り値
`Renumbered { moved }` は動いた `(旧, 新)` の組を、同じ番号の行が何行
あっても 1 度だけ、昇順で列挙する。`u32::MAX` のチャンネルは動く先が
無いのでそのまま残る。

2 ファイルの外にある参照 — TOML 設定・メモ・コード — を直すのは chdef の
仕事ではない。`moved` は、利用側が自分の参照を直す・ずれを通知するのに
必要十分な情報になっている。空き番号で挿入すれば何も動かず、`moved` は
空になる。
